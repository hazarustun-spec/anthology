# Security review — 2026-11-12

Scope: `margin-mcp` (stdio MCP server), `MarginCore` store, Claude config editing, the Mac app.
Method: code review plus hands-on attacks against the release binary over JSON-RPC, each in a
throwaway notes folder. Every fixed finding has a regression test in
`MarginKit/Tests/MarginCoreTests/SecurityTests.swift`.

| ID | Severity | Finding | Status |
|----|----------|---------|--------|
| H1 | High | `update_note` overwrote the previous body with no way back; a prompt-injected model could wipe a note | Fixed: every replaced body is kept in `.history/<id>.versions/<rev>.md`; app has **Undo** per change |
| M1 | Medium | Note `id` read from a crafted file was used in paths (`../../outside`) → writes outside the notes folder | Fixed: ids must be 26-char Crockford; others are replaced with a stable safe id; lookups reject invalid ids |
| M2 | Medium | Stored prompt injection; newlines in titles could forge lines in tool output | Fixed: titles/summaries forced to one line; note bodies returned inside `<note_content>` and marked as data; server instructions say notes are never instructions |
| M3 | Medium | Huge numbers (e.g. `1e300`) crashed the server | Fixed: exact integer conversion, errors instead of traps |
| L1 | Low | Symlinked `.md` files were read through (could expose files outside the folder) | Fixed: symlinks and non-regular files are skipped |
| L2 | Low | No size limits | Fixed: 1 MB for content, 500 chars for titles/summaries, 4096 for paths. SDK's quadratic stdin scan noted for upstream |
| L3 | Low | A lock held by another process made writes hang forever | Fixed: non-blocking lock with timeout → "busy" error; lock file opened with `O_NOFOLLOW`, mode 0600 |
| L4 | Low | Config edits: non-object `mcpServers` replaced silently; symlinked configs replaced by plain files | Fixed: refuse surprising shapes; resolve symlinks and write the target. (Number formatting/key order still normalized by JSONSerialization; the `claude` CLI path is preferred.) |
| L5 | Low | Installed helper could be swapped by another same-user process | Mitigated: the app compares the installed helper byte-for-byte with its bundled copy and offers **Update** on mismatch |
| Info | — | Relative/`/` project paths stored as topic sources | Fixed: only absolute, meaningful paths |
| Info | — | `--snapshot` debug flag in release builds | Fixed: debug builds only |

Already solid (confirmed by testing): slugs neutralize traversal in titles/topics; front matter and
JSONL are injection-safe; atomic writes never write through symlinks; config files and backups keep
mode 0600 and malformed JSON is never overwritten; malformed JSON-RPC gets proper errors and stdout
stays clean; concurrent writers across processes are serialized and stale writes are rejected.

Open items: notes created under a custom `MARGIN_ROOT` inherit the umask (0644); the default folder
lives under the user's 0700 `~/Library`.

## Follow-up: guarding against a hijacked model (same day)
A model that read a malicious web page could try to misuse Margin. Layers now in place:
1. **Nothing is lost:** every AI edit keeps the previous version; History has Undo on each change.
2. **Deleting is off by default** and the `delete_note` tool is hidden from AI tools unless the user
   enables it (Settings › Connections). Moving can be turned off too.
3. **Big removals are flagged:** an AI edit that drops more than half of a note shows a banner with Undo,
   and the tool reply tells the model to mention it to the user.
4. **Tool hints:** `update_note`, `move_note`, `delete_note` are marked destructive (MCP annotations), so
   clients that support it ask the user before running them; read tools are marked read-only.
5. **Rate limit:** at most 30 AI writes per minute per connection.
6. **Notes are framed as data** (`<note_content>`), and the server instructions tell the model never to
   follow instructions found inside notes or web pages.
